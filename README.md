# DailyFlow v0.3 — portable Windows daily tracker

Personal task scheduling with recurring activities, per-day progress, activity output, and reflection. Desktop data stays local. No account or telemetry in the application code. Frontend uses Svelte 5, Vite, Tailwind CSS 4, and locally bundled Plus Jakarta Sans.

## Included

- Add, edit, delete activities; date, start time, planned duration, category, notes.
- Repeat never, daily, Monday–Friday, weekly, or selected weekdays.
- Mark each occurrence done independently. Record actual minutes, activity, output, and daily summary.
- Daily completion progress and past-day history through the date picker.
- Clicking the window X changes the window to a 360×300 desktop widget near the bottom-right of the current monitor. Click the widget to reopen the full interface. Use **Exit DailyFlow** (sidebar) or the power button (widget) to terminate the process.
- Local JSON storage beside the EXE in `DailyFlow-data/tasks.json` for portable backups.

## Build on Windows

Install **Go 1.22+**, **Node.js 20.19+**, **Wails v2 CLI**, and required Windows WebView2 / C++ tooling per the [Wails installation guide](https://v2.wails.io/docs/gettingstarted/installation/). From this folder:

```powershell
go install github.com/wailsapp/wails/v2/cmd/wails@latest
wails doctor
cd frontend
npm install
cd ..
go mod tidy
wails doctor
wails build -clean
```

The `wails.json` file runs `npm install` and `npm run build` as needed. The compiled frontend is embedded in the portable EXE.

## Live UI development

```powershell
cd frontend
npm install
npm run dev
```

Open `http://127.0.0.1:34116` in a browser for a fully interactive **preview with mock tasks in browser localStorage**. No Go build is required for design iteration; preview data is separate from your desktop data.

For native Go integration and Windows widget behavior, run `wails dev` from the project root. Vite HMR is configured for frontend changes.

Expected output is under `build/bin/` (normally `DailyFlow.exe`). Copy the EXE to any writable folder. Keep `DailyFlow-data` alongside it when moving machines. No separate database server required. Size below 50 MB is a **target, not verified** until a Windows build is produced.

## Important limitations of this MVP

- **The Go/Wails backend has not been compiled/tested on Windows yet** in the current environment (Go and Windows build tools unavailable). The Svelte/Vite frontend production build has been verified.
- **No system-tray icon:** closing the window now keeps the process alive as a visible desktop widget, but there is no tray icon. The widget is intentionally *not* always-on-top, so other windows can cover it.
- Widget placement uses Wails v2's current monitor dimensions with a bottom margin approximating a standard Windows taskbar. It may need adjustment on unusual taskbar configurations or multi-monitor layouts.
- Scheduled start/duration are displayed, but do not yet trigger OS notifications or start/stop timers.
- Day summaries are authored by the user, not auto-generated by AI.
- Write access beside the EXE is required; do not put it in `Program Files`.

## Safety notes

Build from this source on your own machine. Review dependencies before compiling. Keep backups of `DailyFlow-data/tasks.json`. Imported/user text is escaped before display, and the frontend has no remote dependencies.
